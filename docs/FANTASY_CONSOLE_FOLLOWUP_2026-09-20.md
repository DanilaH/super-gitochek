# Точечный GitHub-поиск вне Phaser: PICO-8, TIC-80 и Playdate — 2026-09-20

## Зачем и как искали

Продолжение [ручного межстекового обзора](CROSS_STACK_MECHANICS_2026-09-20.md): репозиторный поиск GitHub по PICO-8/game jam, TIC-80/game jam, Playdate/game jam/crank; открытие README, структуры проекта и **конкретных файлов игрового цикла**. Фокус — необычная реализованная механика или полезное несовпадение описания и кода, а не Яндекс Игры, выбор движка или скорость портирования. Ни один проект не запускался; не проверены удобство, удовольствие от геймплея, спрос, права на каждый ассет. Это **целенаправленная, а не случайная выборка**: число поисковых совпадений нельзя выдавать за recall/precision майнера. Не проверялась дедупликация всех ID с `data/discovery-registry.json`, машинная очередь и поисковая политика не изменены.

## Проверено по коду

### [thorny-thorny/parbage](https://github.com/thorny-thorny/parbage) · PICO-8 · переработка, находки и подкуп

[game_scene.lua](https://github.com/thorny-thorny/parbage/blob/master/game_scene.lua): игрок сортирует предметы с ускоряющегося конвейера в подходящие приёмники. Неправильная сортировка повышает раздражение начальника на 20, упавший предмет на 8, а сдача начальнику именно сокровища понижает шкалу на 50. Сокровища можно вместо этого класть в собственную сумку; переполненный пол, истечение смены и недовольство дают отдельные развилки завершения. [garbage.lua](https://github.com/thorny-thorny/parbage/blob/master/garbage.lua) перечисляет виды мусора и сокровища (монета, корона). Механическая находка — встроить риск личной выгоды в повторяющуюся работу, а не просто ещё одну корзину для сортировки. Оригинал уже имеет достаточно много нарисованных предметов, а не нулевую стоимость производства. Не смешивать с ранее изученным Recycler: там ввод слов и взрывы, здесь морально-экономическая развилка и смена.

### [veryprofessionaldodo/Heavens-Kitchen](https://github.com/veryprofessionaldodo/Heavens-Kitchen) · TIC-80/Lua · рецепт как видимая последовательность вещества

[heaven.lua](https://github.com/veryprofessionaldodo/Heavens-Kitchen/blob/master/heaven.lua): три колбы меняются местами под тремя кранами. `fill_flask` накапливает отдельные цветные слои в `fill_order`, при полном заполнении `calculate_score` сопоставляет порядок цветов и доли с первыми тремя заказами; точность долей меняет оценку, наиболее подходящий заказ удаляется. `add_creature` выбирает визуальный результат по порогам оценки. Уровни и arcade имеют таймеры, случайно генерируемые 2–3-компонентные рецепты. Выделяемый цикл: налей в порядке и пропорции → дождись оценки → получи визуальное превращение. Это не свободный алхимический combinator: сравнивается конкретный заказ. README указывает пятерых авторов, много арта/частиц; целый проект нельзя считать малым.

### [deans-code/barrel-and-crank](https://github.com/deans-code/barrel-and-crank) · Playdate/Lua · физический барабанный спуск

[src/lib/common/player/_crosshair.lua](https://github.com/deans-code/barrel-and-crank/blob/main/src/lib/common/player/_crosshair.lua): `playdate.getCrankTicks(12)` и `crankTicks == 1` создают событие выстрела при положительном повороте ручки на 1/12 оборота. Крестовина отдельно двигает прицел, [сцена](https://github.com/deans-code/barrel-and-crank/blob/main/src/lib/stage/carnivalStand/scene2.lua) списывает патрон и применяет результат попадания к очкам/патронам/времени/множителю. [targetManager.lua](https://github.com/deans-code/barrel-and-crank/blob/main/src/lib/stage/carnivalStand/targetManager.lua) уменьшает интервал появления целей от 2000 до 250 мс, содержит пять типов целей. Важная поправка: README рассуждает о ручке для «заряжать и стрелять», **но проверенный код непосредственно стреляет, а не заряжает**; [tempSpeedBoost](https://github.com/deans-code/barrel-and-crank/blob/main/src/lib/common/player/_playerManager.lua) пуст, не записывать его как готовый работающий бонус. По README сделан один тир, другие экраны выбора ещё не игровые уровни.

### [erwinbonsma/RoboRePairPico8](https://github.com/erwinbonsma/RoboRePairPico8) · PICO-8 · ремонт путей, а не роботов

[repair.p8](https://github.com/erwinbonsma/RoboRePairPico8/blob/master/repair.p8): плитки хранят маски входов/выходов; `tilegrid:can_place_tile` и `patch_tile` проверяют совместимость соседних путей. Робот выбирает следующую дорогу по выходам, резервирует клетку или ждёт, если она занята; `bot:_will_meet_with`, `_handle_meeting` и `pair_anim` обрабатывают встречу. При сближении **одинаковых типов** запускается pairing, разных — clash. Механика — косвенное управление движением через редактирование сети. Потребуются правила пересечений и path UX; не выдавать за однокнопочный прототип.

### [foxblock/playdate-crank-it](https://github.com/foxblock/playdate-crank-it) · Playdate/Lua · Bop-It на разных сенсорах

[Source/game_actions.lua](https://github.com/foxblock/playdate-crank-it/blob/main/Source/game_actions.lua): случайный набор команд — направление, кнопка, микрофон, наклон, вынуть/убрать ручку, вращение; для CRANKED накопленный абсолютный поворот достигает **720°**, голос проверяется порогом уровня микрофона, наклон — скалярным произведением акселерометрических векторов. Неверное физическое действие вызывает провал, кроме явно предусмотренной deadzone. [Source/mode_crankit.lua](https://github.com/foxblock/playdate-crank-it/blob/main/Source/mode_crankit.lua): очки за верный отклик, таймер, уровни скорости; ограничение времени по уровням задано массивами в `game_actions.lua`. Интерес — смена моторных задач с растущим темпом. Физические датчики/ручка — часть самой механики, веб-версия без них потребует самостоятельного дизайна, а не прямого порта.

## Следствие для исследовательского процесса

Ранее в `discovery_policy.py` не было самостоятельных PICO-8/TIC-80/Playdate запросов, но ручной поиск доказал лишь наличие ценных исходников **вне привычного поискового фокуса**, а не статистическое превосходство запроса или отсутствие этих ID в накопленном каталоге. Не запускали новый массовый скан и не меняли курсоры/категории. При будущем сравнении считать только уникальные GitHub ID после дедупликации, отдельно — проверенные по исходникам необычные механики, и обязательно отмечать форки/шаблоны/README-only; автоматический score жанра не заменяет ручную оценку.
