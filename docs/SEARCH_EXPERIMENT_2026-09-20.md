# Game Miner — проверка поисковой стратегии (2026-09-20)

**Цель:** получить больше новых *проверяемых игровых механик*, а не максимизировать число репозиториев. Это ручной небольшой A/B-пилот с живым GitHub Search и точечной проверкой README/кода, **не** доказательство общей статистической эффективности и **не** новый массовый прогон `incremental_scan.py`. Исходный каталог шестого скана: 539 автоматически инспектированных репозиториев; поиск по нему был сделан по `full_name`, а не по описаниям.

## Метод

На момент проверки для каждой из трёх тем запросили страницу 1, `per_page=10`, одинаковые фильтры `is:public fork:false archived:false size:<30000` и сортировку GitHub по умолчанию:

| Тема | A — существующий запрос | B — более узкий запрос | Получено |
| --- | --- | --- | --- |
| Incremental | `phaser incremental game in:name,description,readme` | `phaser incremental game in:name,description` | 10 / 10 |
| Fishing | `phaser fishing game in:name,description,readme` | `phaser fishing game in:name,description` | 10 / 10 |
| Mining | `phaser mining game in:name,description,readme` | `phaser mining game in:name,description` | 10 / 8 |

Это **три парных поисковых запроса**, а не 58 независимых игр: результаты могут пересекаться по GitHub ID и содержать пустые/незаконченные проекты. Для incremental дополнительно проверена страница 11 старого запроса (`per_page=10`) и страница 2 узкого запроса. Ссылка на воспроизведение: [репозиторный поиск GitHub](https://github.com/search?q=phaser+incremental+game+in%3Aname%2Cdescription&type=repositories), а точные строки запросов и параметры приведены выше.

### Наблюдения

- **A / incremental:** среди 10 позиций — `awesome-open-source-games`, `awesome-jsgames`, `awesome-pwa`, `desloppify`, `learn-harness-engineering`, `Mechaduino-Hardware`, `rosie`, `yakui`; `tamagotchiClone` действительно содержит игру, `gamedevsam/phaser` требует отдельного разбора. Не считать эти 10 позициями с 10 playable games.
- **A / fishing:** `jojoee/phaser-examples` и `invalid0190/eye_minigames` — потенциально полезные *сборники*, но не игры про рыбалку; оставшиеся результаты включают Minecraft/Bukkit-моды, WoW-бота, документацию по accessibility, наборы skills и т.п. `eye_minigames` ранее дал реальную находку из вложенных модулей — поэтому полностью удалять поиск по README опасно.
- **A / mining:** на странице оказались учебные подборки, Web3, лотерейный проект и `z0mbiesrock/Diamond-Ore`, который, согласно README, является модом к другой игре, а не самостоятельной Phaser-игрой.
- **B / incremental:** получили предметные кандидаты, включая `berkaycit/smashloop`, `mexedes/dungeon-idle`, `thechaoticatmospheres/little-waters`, `Kumaken/DiggettyClicker`. Но последний README прямо называет этот репозиторий заброшенным и указывает на другой; `Aristona/Phaser.Adventure-Capitalist` в README откладывает магазины, апгрейды и менеджеров на будущее. Само попадание в B не подтверждает зрелость игры.
- **B / fishing:** в 10 позициях имена преимущественно относятся к рыболовным играм; есть проекты размером 1–14 КБ и слот-игра. Их работоспособность и соответствие низкому production burden **не проверены**.
- **B / mining:** из 8 позиций одна явно блокчейн-тематики (`BlockchainLabs/SaluS`), зато найден `variaplay/ore-drift`, реальную добычу/топливо/риск потери руды подтвердили по исходнику.
- **A / incremental, стр. 11:** получено ещё 10 репозиториев, среди них AI-промпты, Scrum-тесты, синхронизатор сохранений, инструменты и фреймворк Unity. Глубина выдачи **сама по себе** не показала улучшения качества на этом контрольном срезе. **B / incremental, стр. 2:** пусто при `per_page=10` в момент проверки; это не показатель всех тематических запросов.

### Новые механики с кодовой опорой, которых не было в каталоге шестого скана

1. **[Smashloop](https://github.com/berkaycit/smashloop)** — Phaser 3 / TypeScript Breakout с монетами за кирпичи и деревом апгрейдов: здоровье платформы, ширина, выстрелы, множитель монет, ракета; уровни и покупки сохраняются в `localStorage`. [README](https://github.com/berkaycit/smashloop/blob/main/README.md), [upgrades.ts](https://github.com/berkaycit/smashloop/blob/main/src/game/upgrades.ts), [persistence.ts](https://github.com/berkaycit/smashloop/blob/main/src/game/persistence.ts). Код MIT в корневом [LICENSE](https://github.com/berkaycit/smashloop/blob/main/LICENSE), права на все медиа отдельно не проверены. **Риск:** обычный Breakout может быть производственно простым, но не уникальным; наличие апгрейдов ≠ привлекательность/спрос.
2. **[Ore Drift](https://github.com/variaplay/ore-drift)** — Phaser 3, Slither-like управление с автообстрелом метеоритов и сбором руды. В `GameScene.js` попадания в метеоры при высокой скорости отнимают 4 единицы топлива и выбивают часть груза; есть NPC, апгрейды и восстановление/сохранение прогресса в отдельных модулях. [README](https://github.com/variaplay/ore-drift/blob/main/README.md), [GameScene.js](https://github.com/variaplay/ore-drift/blob/main/src/scenes/GameScene.js). Корневой `LICENSE` при проверке не найден; изучать как референс идеи, **не копировать код/ассеты**. **Риск:** NPC, физика, управление и баланс повышают стоимость переноса, не считать лёгким MVP.

Ещё два отсутствовавших в старом каталоге кандидата: [Dungeon Idle](https://github.com/mexedes/dungeon-idle) — README и `src/scenes/MainScene.ts` подтверждают Phaser-сцену с idle tick, тапом, покупками и престижем; [Little Waters](https://github.com/thechaoticatmospheres/little-waters) — README описывает крупный React/Phaser-аквариум с торговлей/разведением, явно более сложный production scope. Ни один не объявлен коммерчески перспективным на основании исходников.

## Решение по внедрению

1. **Исправить проверяемый дефект курсоров.** Прежний код ограничивал обход 10 страницами и сохранял только номер страницы без `per_query`. Исправленный `incremental_scan.py` допускает страницы до лимита GitHub Search в 1 000 результатов на запрос, хранит `query_page_sizes` и при несовпадении/неизвестном старом размере безопасно возвращается к странице 1. GitHub ID уже просмотренных кандидатов дедуплицируются; на миграционном прогоне часть запросов повторит первую страницу. Регрессионные тесты проверяют 11-ю страницу, миграцию старого состояния, смену размера и отсутствие повторной инспекции.
2. **Добавить B как три отдельных запроса, не удаляя A.** Это ограниченный rollout с проверенным обнаружением новых кандидатов. Сохраняем широкие README-запросы для сборников/неочевидных игр, но далее сравниваем отдачу по каждому запросу отдельно.
3. **Записывать `search_query_stats.json`:** `hits`, `new_unique_queued`, `already_inspected_hits`, `new_irrelevant`, `pages_fetched`. Эти значения автоматически вычисляются по GitHub ID и эвристическому precheck; **они не измеряют качество геймплея, лицензии или количество подтверждённых механик**. Число действительно проверенных игровых циклов остаётся ручным полем курируемого журнала.
4. **Не включать пока автоматическое чтение всего README/кода и рекурсивный поиск мини-игр.** Данные пока подтверждают необходимость *точечной* кодовой проверки shortlist и отдельной работы со сборниками, но не оправдывают дорогое индексирование каждого файла. Не добавлять десятки новых тематических запросов до наблюдения за отдачей текущих трёх.

## Проверка и ограничения

- Локальные тесты изменённого сканера на фейковом GitHub API: сценарии 11-й страницы и смены `per_query` прошли. Реальные GitHub Actions для [тестов регрессии](https://github.com/DanilaH/super-gitochek/actions/runs/35464007292) и [добавленных запросов](https://github.com/DanilaH/super-gitochek/actions/runs/35464048850) завершились успешно.
- Запуск `workflow_dispatch` с новым массовым сканированием **не проводился**; не приписывать эксперименту новые значения `total_catalog` и `pending`. Не проводился запуск/прохождение найденных игр в браузере, проверка каждого ассета или исследование Яндекс-спроса.
- Выборка небольшая, нерандомизированная и из близких Phaser-запросов. Ранжирование GitHub и индекс README меняются. Сравнение эффективности в следующих прогонах должно учитывать число *новых подтверждённых игровых циклов на единицу исследовательского бюджета*, а не только `new_unique_queued`.
