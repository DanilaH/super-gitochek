# Game Miner — decisions

## 2026-09-19 — D-001: хранить ручные игровые находки в репозитории

**Решение:** основной журнал *интересных идей и проверенных вручную механик* — [`GAME_IDEAS.md`](GAME_IDEAS.md). Ссылка также размещается в корневом `README.md`. При следующем скане дополнять журнал, не заменяя машинным рейтингом и не теряя ранее отмеченные кандидаты.

**Почему:** история отдельного чата и временные артефакты GitHub Actions не гарантируют полное восстановление ручных выводов в другой беседе. `data/discovery-registry.json` остаётся источником истины о факте обнаружения/инспекции репозитория, но **не** об интересности, спросе, качестве и лицензиях. README и выборочные файлы кода — ещё не запуск игры и не проверка прав.

**Границы:** не смешивать этот каталог с самостоятельными игровыми концепциями пользователя; не приписывать непроверенный коммерческий потенциал. Технические изменения майнера и решения по реализации фиксировать отдельно при их появлении.

Проверка кода не заменяет запуск, тест тактильности и проверку спроса.

## 2026-09-20 — D-004: исправить курсоры; проверить узкие запросы, не заменяя широкие

**Эксперимент и подробная методика:** [SEARCH_EXPERIMENT_2026-09-20.md](SEARCH_EXPERIMENT_2026-09-20.md). Три пары живых запросов Phaser (`incremental`, `fishing`, `mining`) при `per_page=10` показали, что `in:name,description,readme` на первой странице сильно засоряется посторонними README. `in:name,description` дал несколько новых содержательных кандидатов, включая Smashloop и Ore Drift с проверенной по коду механикой. Но README-поиск нашёл коллекцию eye_minigames, которую узкие запросы могли бы упустить. Выборка мала; не интерпретировать это как гарантированный процент улучшения.

**Внедрено:** исправлено прежнее ограничение в 10 страниц и несовместимость курсора со сменой `per_query` (при старом неизвестном размере первая страница повторно запрашивается, ранее просмотренные GitHub ID не инспектируются повторно). Добавлены три узких запроса **параллельно** старым широким; создан `search_query_stats.json` с измерением поисковой отдачи по запросу. Автоматическое глубокое чтение исходников и массовое индексирование всех вложенных папок **не внедрены**: их ROI ещё не доказан. Регрессионные тесты и GitHub Actions CI после изменений прошли; новый `workflow_dispatch` со сканированием не запускался, последний полный каталог остаётся 539 / 10.

**Ограничения:** `new_unique_queued` не равно количеству пригодных игр; в курируемых журналах хранить ссылку на исходник для каждого подтверждённого игрового цикла. Изменение ранжирования GitHub и лимит первых 1 000 результатов на запрос мешают гарантированно полному обходу; статистика по одному срезу выдачи не измеряет спрос на Яндекс Играх.

## 2026-09-20 — D-005: контрольный скан выполнен; сначала разобрать очередь

**Факты:** [CONTROL_SCAN_07_2026-09-20.md](CONTROL_SCAN_07_2026-09-20.md) — полный отчёт по [успешному run 65](https://github.com/DanilaH/super-gitochek/actions/runs/35464553481): `inspect=30`, `per_query=30`, `pages=1`; каталог **539 → 569**, очередь **10 → 236**, три новых узких запроса добавили **34 новых для реестра ID**, из которых пока автоматически инспектированы три. Это не 34 пригодные игры. `29 game / 1 tool` в new.json — только ненадёжная метка; `shaocloud/miner-game` оказался шаблоном с дефолтной сценой, а `DiggettyClicker` помечен автором как discontinued. `Crystal Clicker` — проверенный по коду цикл «атакуй или ремонтируй», но его апгрейды при рестарте сбрасываются вопреки тексту README. Скан не включал живой playtest или анализ спроса.

**Решение:** новые узкие запросы сохраняем рядом с широкими. **Не запускать новый массовый скан, пока не разобраны 31 ожидающий кандидат этой тройки и не измерены подтверждённые механики/затраты на проверку.** Не повышать бюджет `inspect` ради числа карточек. Классификатор `game` считать `game candidate`, различать шаблоны, незавершённые игры и кодово подтверждённые игровые циклы. Массовое чтение исходников/мини-игр не строить без доказанной отдачи. `Crystal Clicker` — один кандидат для отдельного live-playtest, не решение начать разработку и не утверждение о трафике.

**Безопасность workflow:** одноразовый запуск был разрешён только конкретным сообщением push-коммита; исходный режим `workflow_dispatch` восстановлен, [run 66](https://github.com/DanilaH/super-gitochek/actions/runs/35464695467) успешен. Последний числовой срез теперь 569/236, а упоминания 539/10 в D-002–D-004 — исторические.
